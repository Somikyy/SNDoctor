# Как участвовать в разработке

Спасибо, что заглянул. Ниже всё, что нужно знать, чтобы твой pull request приняли без
долгой переписки.

---

## Самое полезное, что можно сделать за пять минут

**Прислать недостающее Spigot-имя.** Таблица соответствий Spigot → Mojang лежит в
[`src/main/resources/sndoctor/spigot-names.txt`](src/main/resources/sndoctor/spigot-names.txt).
Сейчас в ней 105 записей — это далеко не весь NMS.

Формат простой, одна строка на имя:

```
EntityPlayer=ServerPlayer
NBTTagCompound=CompoundTag
```

Если ты видел в чужом плагине Spigot-имя, которого у нас нет, — открой PR с одной строкой.
Это реально помогает: чем полнее таблица, тем меньше плагинов проскакивает мимо проверки.

## Сборка

Нужен только JDK 17 или новее. Больше ничего ставить не надо.

```bash
bash tools/offline/verify.sh
```

Это собирает плагин **без доступа в интернет** и прогоняет весь набор утверждений.
Компиляция идёт против крошечных заглушек Bukkit из `tools/offline/bukkit-stubs`, которые
не попадают в итоговый jar — настоящие классы даёт сервер.

Скрипт работает и в Git Bash на Windows, и на Linux: из внешних программ ему нужны только
`javac`, `java`, `bash` и `perl`, а все четыре идут в комплекте с JDK и с Git.

Обычная сборка через Gradle тоже есть, но ей нужен доступ к `repo.papermc.io`:

```bash
gradle build
```

**Перед отправкой PR прогон `verify.sh` должен быть зелёным.** Это не формальность:
офлайн-набор — единственное, что защищает проект от ложных срабатываний.

## Устройство проекта

```
src/main/java/network/somikyy/sndoctor/
├── core/     ← ноль импортов org.bukkit, здесь вся логика анализа
├── report/   ← рендереры отчёта (текст, JSON)
├── cli/      ← Main-Class, тоже ноль Bukkit
└── bukkit/   ← единственный слой, который знает про сервер
```

**`core/`, `cli/` и `report/` никогда не импортируют `org.bukkit`.** Именно это позволяет
запускать SNDoctor как обычную программу на машине, где сервера нет вообще, — а он нужнее
всего как раз тогда, когда сервер не стартует. Инвариант проверяется в CI грепом, так что
случайный импорт не проедет.

Правила анализа живут в [`core/Analyzer.java`](src/main/java/network/somikyy/sndoctor/core/Analyzer.java).

## Если трогаешь заглушки Bukkit

`tools/offline/bukkit-stubs/` — это compile-only копии сигнатур сервера, нужные для сборки без
сети. Правило одно, но железное:

**Сигнатура заглушки обязана совпадать с настоящей дословно, включая возвращаемый тип.**

Дескриптор метода в JVM включает возвращаемый тип, поэтому заглушка

```java
Object runTaskAsynchronously(Plugin plugin, Runnable task);   // а сервер отдаёт BukkitTask
```

компилируется без единого предупреждения — и роняет плагин на живом сервере с
`NoSuchMethodError`, потому что метода с таким дескриптором нет ни у кого. Именно так была
сломана первая сборка 1.0.0.

Проверять на глаз это не нужно, за этим следят машины:

- самотест сверяет дескрипторы каждой сборки с записанным
  [`tools/offline/bukkit-api-surface.txt`](tools/offline/bukkit-api-surface.txt);
- CI собирает те же исходники против настоящего paper-api и сравнивает наборы ссылок целиком;
- в релиз уходит jar, собранный против настоящего API, а не против заглушек.

Если ты сознательно расширил используемое API — перезапиши запись и приложи её к PR:

```bash
bash tools/offline/build-offline.sh
bash tools/offline/api-surface.sh build/offline/classes > tools/offline/bukkit-api-surface.txt
```

## Как добавить правило

Порядок именно такой, короткие пути ведут к ложным срабатываниям:

1. **Найти первоисточник.** Анонс PaperMC, пометка `@Deprecated` в javadoc, коммит в
   Paper — что-то, на что можно сослаться. «Я слышал, что это сломалось» источником не
   является.
2. Добавить метод `checkXxx` в `Analyzer` и зарегистрировать его в `analyze()`.
3. Добавить фикстуру и утверждение в [`tools/offline/selftest.sh`](tools/offline/selftest.sh).
4. Внести строку в таблицу раздела 4 файла [`docs/SPEC-SNDoctor.md`](docs/SPEC-SNDoctor.md)
   со ссылкой на источник.

**Правило без фикстуры не считается сделанным.** Правило, которое «выглядит правильно» в
коде, ничего не стоит: единственный способ убедиться, что читатель constant pool реально
видит `EntityPlayer` — скомпилировать класс, который на него ссылается, и проверить, что
находка появилась.

### О цене ошибки

Одно ложное «не запустится» стоит дороже десяти пропущенных проблем. Админ, которому
SNDoctor соврал про рабочий плагин, больше не поверит ни одной строчке отчёта — и правильно
сделает. Поэтому когда есть сомнения, находка идёт в раздел «на ручную проверку», а не в
красные.

Раздел 4.6 спеки хранит правила, которые **проверялись и не подтвердились**. Если ты
проверил гипотезу и она не подтвердилась — это тоже ценный PR, допиши её туда.

## Стиль кода

- **Java 17.** Не 21 и не 25: SNDoctor должен запускаться на тех самых старых серверах,
  которые он диагностирует. Повышать версию — только с обоснованием.
- Пакет `network.somikyy.sndoctor`, четыре пробела отступа, длина строки около 110.
- **Ноль runtime-зависимостей.** `compileOnly` для API сервера — норма, `implementation`
  требует обоснования в описании PR. Всё, что зашейдено внутрь, — это потенциальный
  конфликт на чужом сервере, а SNDoctor кладут на сервер, который уже сломан.
- **Комментарий объясняет «почему», а не «что».** `// увеличиваем счётчик` — мусор.
  `// объявленное, но неиспользуемое поле не оставляет CONSTANT_Class` — польза.
- Тексты для пользователя — полными предложениями, по-русски, без жаргона и кодов ошибок.
  Английский вариант добавляется рядом, а не «потом».
- Вывод всегда с явной кодировкой UTF-8: «иероглифы в консоли» лечатся на нашей стороне,
  а не флагом `-Dfile.encoding` в скрипте запуска у админа.
- Не оставляй `TODO` без имени и даты.

## Оформление PR

- Одна тема на один PR. «Добавил правило и заодно переименовал три класса» ревьюить нечем.
- В описании — что изменилось и почему; для нового правила обязательна ссылка на источник.
- Приложи вывод `verify.sh`.

## Лицензия вклада

Проект под **GPL-3.0-or-later**. Отправляя pull request, ты соглашаешься, что твой код
распространяется на тех же условиях. Заголовок лицензии есть в каждом `.java` — при
создании нового файла скопируй его из соседнего.

## Нашёл ошибку, но чинить не хочешь

Тоже хорошо — заведи issue. Особенно ценно ложное срабатывание: приложи название и версию
плагина, на котором SNDoctor соврал, и что он написал.
