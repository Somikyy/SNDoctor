# SNDoctor — техническое задание

**Версия документа:** 1.0 · 1 августа 2026
**Статус:** v1.0.0 реализована, самотест зелёный
**Лицензия:** GPL-3.0-or-later
**Целевая платформа:** Paper 1.21+ и 26.x, Java 17+ (режим CLI — где угодно, где есть Java 17)

---

## 1. Зачем это существует

### 1.1 Боль

С версии **26.1 (24 марта 2026)** Mojang перестал отдавать обфусцированные server-jar'ы, а Paper
полностью выкинул внутренний ремаппер. Формулировка PaperMC дословно:

> «If your plugin is still using Spigot-mapped internal names (such as obfuscated class/field/method
> names or Spigot names like `EntityHuman` and `PacketPlayIn...`), please prepare migration as soon
> as you can, **as your plugin will not work on 26.1**.»
> — [papermc.io/news/1-21-11](https://papermc.io/news/1-21-11/), 21 декабря 2025

Масштаб последствий (данные Modrinth search API, 1 августа 2026):

| Версия | Плагинов с поддержкой |
|---|---|
| 1.21.4 | 12 631 |
| 1.21.11 | 9 972 |
| 26.1 | 4 264 |
| **26.2** | **2 532** |
| всего плагинов на Modrinth | 16 482 |

Примерно **85% экосистемы ещё не перешло рубеж 26.x**. Админ, который решает обновиться, сейчас
может узнать, что у него сломается, только одним способом: обновиться и смотреть, что упало.

### 1.2 Чего нет на рынке

Инкумбента нет. Ближайшее — Plugin Portal, где распознавание установленных плагинов и
автообновление стоят $15, и это про обновление, а не про совместимость с новой мажорной версией.

Канонический совет комьюнити по диагностике до сих пор — [статья от 8 декабря 2019](https://madelinemiller.dev/blog/debug-minecraft-server-issues/)
с правками до февраля 2021: «удали половину плагинов и перезапусти, потом ещё половину». Вручную.

### 1.3 Что делает SNDoctor

Читает папку `plugins/`, разбирает каждый jar и говорит по каждому плагину: **запустится / запустится
с проблемами / не запустится**, с конкретными доказательствами из байткода и ссылкой на первоисточник.

### 1.4 Критерий успеха

- Админ запускает один раз перед обновлением и получает список того, что сломается.
- Отчёт умещается в один скриншот и понятен без знания Java.
- **Ноль ложных «красных».** Ложное «не запустится» стоит дороже, чем пропущенная проблема:
  первое ломает доверие ко всему инструменту.

## 2. Границы задачи

### 2.1 Что входит в v1.0

- Статический анализ jar-файлов без запуска и загрузки их кода.
- Два режима из одного файла: плагин и standalone CLI.
- Отчёт в консоль, в текстовый файл и в JSON.
- Русский и английский языки вывода.
- Эвристики безопасности, вынесенные в отдельную ось (не влияют на вердикт совместимости).

### 2.2 Что НЕ входит в v1.0

- Автоматическое обновление плагинов — это отдельный продукт (SNUpdater).
- Поиск замен по каталогам Modrinth/Hangar — v1.1, требует сети.
- HTML-отчёт — v1.1.
- Анализ конфигов плагинов.
- Динамический анализ, песочница, запуск кода.

### 2.3 Явные не-цели

**SNDoctor не антивирус.** Эвристики безопасности отвечают на вопрос «стоит ли посмотреть глазами»,
а не «это вредонос». Формулировки в отчёте это отражают, и такие находки никогда не окрашивают
плагин в красный.

## 3. Архитектура

### 3.1 Ключевое решение: ноль зависимостей

SNDoctor не тянет ни одной runtime-зависимости. Ни ASM, ни SnakeYAML, ни JSON-библиотеки.

Обоснование:

1. **Инструмент нужен тогда, когда сервер уже сломан.** Всё, что он шейдит, — это ещё один способ
   конфликтовать с классами на сломанном classpath.
2. **CLI-режим обязан работать без сервера.** SnakeYAML предоставляет Bukkit, но в CLI Bukkit'а нет.
3. **Размер.** Итоговый jar — около 70 КБ. Это влияет на решение «скачать и попробовать».
4. **Доверие.** Плагин на 70 КБ с открытым кодом и без зависимостей проверяется глазами за вечер.
   В RU-сегменте после разбора бэкдора в мае 2026 это не абстрактное преимущество.

Цена решения: свой ридер class-файлов (~230 строк) и свой ридер plugin.yml (~180 строк).

### 3.2 Слои

```
network.somikyy.sndoctor
├── core/            ← ни одного Bukkit-класса, работает где угодно
│   ├── ClassFileReader   разбор constant pool + дескрипторов полей и методов
│   ├── MiniYaml          подмножество YAML, достаточное для plugin.yml
│   ├── JarScanner        обход zip-архива, сбор фактов
│   ├── JarFacts          факты об одном jar
│   ├── Analyzer          правила → находки
│   ├── Finding           одна находка (id, severity, ru/en текст, доказательства)
│   ├── Report            вердикты и сводка
│   └── ScanService       единственная точка входа для обоих фронтов
├── report/
│   ├── TextRenderer      консоль и файл, ANSI опционально
│   └── JsonRenderer      машинный формат, без JSON-библиотеки
├── cli/SNDoctorCli       Main-Class
└── bukkit/SNDoctorPlugin единственный класс, который знает про Bukkit
```

**Инвариант:** пакет `core` и пакет `cli` не импортируют `org.bukkit.*`. Нарушение этого инварианта
ломает CLI-режим на машине без сервера. Проверяется в CI грепом.

### 3.3 Почему свой парсер class-файлов, а не ASM

SNDoctor нужен только constant pool плюс таблицы полей и методов. Это примерно 230 строк по JVMS
глава 4. ASM — 120+ КБ ради того же результата, плюс необходимость релокации.

**Важная деталь, найденная самотестом.** Первая версия читала только constant pool. Оказалось, что
класс, который объявляет

```java
public EntityPlayer handle;
```

и никогда к этому полю не обращается, **не создаёт** ни `CONSTANT_Class`, ни `Fieldref` для
`EntityPlayer` — тип живёт только внутри дескриптора поля. Пропуск секций `field_info` и
`method_info` терял реальные NMS-обращения, то есть ровно то, ради чего инструмент написан.
Сейчас читаются обе секции.

## 4. Правила

### 4.1 Политика правил

**Каждое правило опирается на первоисточник:** анонс PaperMC, пометка deprecated в javadoc или
наблюдаемое свойство самого jar. Правила, которые не удалось подтвердить первоисточником, в набор
не включены — см. раздел 4.6.

Обоснование: сканер совместимости, сообщающий об изменении, которого не было, приносит вред. Один
ложный «красный» — и админ перестаёт верить всему отчёту.

### 4.2 Уровни серьёзности

| Уровень | Значение | Влияет на вердикт |
|---|---|---|
| `BLOCKER` | не загрузится или упадёт на 26.1+ | КРАСНЫЙ |
| `BREAKING` | функция молча перестала работать | ЖЁЛТЫЙ |
| `WARN` | депрекейт, изменение поведения, рискованная зависимость | ЖЁЛТЫЙ |
| `INFO` | справка | нет |
| `SECURITY` | нужен взгляд человека | **нет, отдельная секция** |

Вердикт плагина: КРАСНЫЙ если есть хоть один BLOCKER, иначе ЖЁЛТЫЙ если есть BREAKING или WARN,
иначе ЗЕЛЁНЫЙ. Нечитаемый файл — ПРОПУЩЕН.

Код возврата CLI: `2` — есть красные, `1` — есть жёлтые, `0` — чисто. Годится для CI.

### 4.3 Правила совместимости

| id | Уровень | Срабатывает на | Источник |
|---|---|---|---|
| `nms.spigot-mappings` | BLOCKER | ссылка на `net/minecraft/**` с именем класса из таблицы Spigot-имён | [PaperMC 1.21.11](https://papermc.io/news/1-21-11/) |
| `nms.legacy-versioned-package` | BLOCKER | `net/minecraft/server/v1_XX_RX/**` | пакет исчез в 1.17 |
| `craftbukkit.versioned` | BLOCKER | `org/bukkit/craftbukkit/v1_XX_RX/**` | релокация убрана в 1.20.5 |
| `meta.main-class-missing` | BLOCKER | `main` из дескриптора отсутствует в архиве | содержимое jar |
| `java.too-new` | BLOCKER | class major version выше, чем Java сервера | JVMS |
| `api.teleport-flag-entitystate` | BREAKING | `TeleportFlag$EntityState` | [Paper 1.21.9/1.21.10](https://papermc.io/news/1-21-9-and-10/): «no longer has any functionality» |
| `nms.version-reflection` | WARN | строковая константа вида `v1_XX_RX` | релокация убрана в 1.20.5 |
| `api.conversation` | WARN | `org/bukkit/conversations/**` | Paper 1.21.9/1.21.10 + javadoc 26.2 deprecated-list |
| `api.metadata` | WARN | `org/bukkit/metadata/**`, `setMetadata`/`getMetadata` | Paper 1.21.9/1.21.10 |
| `api.player-spawn-location-event` | WARN | `PlayerSpawnLocationEvent` | Paper 1.21.9/1.21.10 |
| `api.legacy-material` | WARN | `org/bukkit/material/**`, `Material#getId`, `ItemStack#getDurability` | легаси до 1.13 |
| `meta.no-api-version` | WARN | нет `api-version` в plugin.yml | поведение загрузчика |
| `meta.ancient-api-version` | WARN | `api-version` < 1.13 | флаттенинг 1.13 |
| `dep.protocollib` | WARN | `com/comphenix/protocol/**` или depend | последний релиз 5.4.0 от 2025-08-09 |
| `scan.unreadable-classes` | WARN | не удалось разобрать часть классов | наблюдение |
| `api.gamemode-change-cause` | INFO | `PlayerGameModeChangeEvent` | Paper 1.21.9: новая причина `GAMEMODE_SWITCHER` заменяет `COMMAND` |
| `craftbukkit.direct` | INFO | `org/bukkit/craftbukkit/**` без версии | наблюдение |
| `dep.vault` | INFO | `net/milkbowl/vault/**` или depend | Vault без обновлений с 2020 |
| `meta.paper-plugin` | INFO | есть `paper-plugin.yml` | наблюдение |
| `meta.runtime-libraries` | INFO | непустая секция `libraries:` | наблюдение |
| `meta.not-a-plugin` | INFO | нет ни одного дескриптора | наблюдение |
| `folia.supported` | INFO | `folia-supported: true` | наблюдение |
| `java.required` | INFO | максимальная class major version | JVMS |

### 4.4 Таблица Spigot-имён

Ресурс `sndoctor/spigot-names.txt`, формат `SpigotName=MojangName`, 105 записей на момент 1.0.0.

В таблицу попадают **только** имена, существующие исключительно в наборе Spigot-маппингов.
Имена, совпадающие в обоих наборах (`Entity`, `ItemStack`, `MinecraftServer`, `Packet`, `Scoreboard`,
`Chunk`), намеренно отсутствуют — они ничего не доказывают и дали бы ложные срабатывания.

Расширяется без пересборки:
- режим плагина: `plugins/SNDoctor/spigot-names.txt`
- режим CLI: `--names <файл>`

### 4.5 Эвристики безопасности

Никогда не влияют на вердикт совместимости. Выводятся отдельной секцией с формулировкой
«на ручную проверку».

| id | Срабатывает на |
|---|---|
| `sec.process-execution` | `Runtime#exec`, `ProcessBuilder` |
| `sec.dynamic-class-loading` | `URLClassLoader`, `defineClass` |
| `sec.suspicious-endpoints` | URL с сырым IP, пейстбины, вебхуки, туннели |
| `sec.server-files` | упоминания `rcon.password`, `ops.json`, `usercache.json` и т.п. |
| `sec.masquerading-package` | 1–4 класса внутри пакета известной библиотеки |

Про последнюю отдельно. Настоящий шейдинг библиотеки приносит сотни её классов. Если внутри
`org/apache/commons/lang3/` лежит один-два класса — это не шейдинг, это чужой код в чужом пакете.
Ровно такой формы был бэкдор, разобранный в RU-комьюнити в мае 2026: класс `MutableUtilities`,
замаскированный под `org.apache.commons.lang3`.

### 4.6 Правила-кандидаты (НЕ реализованы)

Проверялись и **не подтвердились** первоисточником. В коде их нет намеренно.

| Кандидат | Статус |
|---|---|
| Идентификаторы геймрулов сменились с camelCase на snake_case | Не подтверждено. В анонсе Paper 1.21.9/1.21.10 такого нет. Правило не добавлено. |
| Методы длительности у `WorldBorder` перешли с миллисекунд на тики | Не подтверждено там же. Правило не добавлено. |

Если найдётся первоисточник — правила добавляются вместе со ссылкой на него в этой таблице.

## 5. Интерфейсы

### 5.1 CLI

```
java -jar SNDoctor.jar [папка] [флаги]
```

Без аргумента берётся `./plugins`, а если её нет — текущая папка.

| Флаг | Смысл |
|---|---|
| `--java <N>` | Java, на которой будет крутиться сервер. Без неё нельзя сказать «плагину нужна Java новее». |
| `--json <файл>` | машинный отчёт |
| `--out <файл>` | полный текстовый отчёт |
| `--names <файл>` | свой список Spigot-имён поверх встроенного |
| `--lang ru\|en` | язык, по умолчанию `ru` |
| `--full` | показывать INFO-находки и перечислять зелёные плагины |
| `--no-color` | без ANSI |

### 5.2 Команда в игре

```
/sndoctor [scan|full|version|reload] [--lang ru|en]
```

Права: `sndoctor.use` для проверки, `sndoctor.reload` для перечитывания конфига; оба по умолчанию
`op`. Алиасы `/snd`, `/sndoc`, `/снд`.

Сканирование идёт асинхронно (чтение десятков jar — дисковая работа, главный поток трогать нельзя).
В чат уходит сводка и первые десять красных, полный отчёт пишется в
`plugins/SNDoctor/reports/report-<timestamp>.txt` и `.json`.

### 5.3 Конфигурация

`plugins/SNDoctor/config.yml` создаётся при первом запуске копированием ресурса из jar.

Читается **собственным** `MiniYaml`, а не конфигурационным API Bukkit. Bukkit тут сработал бы, но
весь смысл плагина в том, что его кладут на сломанный сервер и он ничего своего не приносит:
переиспользование парсера, который уже лежит в jar, оставляет поверхность контакта с Bukkit равной
пяти классам и гарантирует, что файл разбирается одинаково во всех режимах.

| ключ | по умолчанию | смысл |
|---|---|---|
| `general.language` | `ru` | язык отчёта и файлов; `--lang` перекрывает на один запуск |
| `general.update-check` | `true` | один async-запрос к api.github.com при старте; `false` — плагин не открывает сокетов вообще |
| `scan.on-start` | `true` | автопроверка после запуска сервера, итог в консоль |
| `scan.start-delay` | `100` | задержка автопроверки в тиках, обрезается диапазоном `0…12000` |
| `scan.full` | `false` | включать ли INFO-находки |
| `reports.enabled` | `true` | писать ли отчёты на диск |
| `reports.json` | `true` | писать ли `.json` рядом с `.txt` |
| `reports.keep` | `20` | сколько последних проверок хранить, `0` — не удалять |

Все числовые значения обрезаются диапазоном при загрузке, а нечитаемый файл откатывается на
значения по умолчанию с предупреждением в лог: конфиг, отредактированный руками, не должен ронять
диагностический инструмент.

### 5.4 Формат JSON

Стабильный контракт для внешних инструментов — Telegram-бота, веб-панели, CI.

```json
{
  "tool": "SNDoctor",
  "toolVersion": "1.0.0",
  "target": "26.1+",
  "scannedPath": "/srv/mc/plugins",
  "serverJava": 21,
  "serverVersion": "",
  "durationMillis": 41,
  "summary": { "total": 8, "red": 2, "yellow": 2, "green": 3, "skipped": 1, "needsReview": 1 },
  "plugins": [
    {
      "file": "LegacyPlugin.jar",
      "name": "LegacyPlugin",
      "version": "1.0",
      "main": "fixture.legacy.LegacyMain",
      "apiVersion": "",
      "foliaSupported": false,
      "paperPlugin": false,
      "requiredJava": 17,
      "classes": 1,
      "authors": [], "depend": [], "softDepend": [],
      "verdict": "RED",
      "findings": [
        {
          "id": "nms.spigot-mappings",
          "severity": "BLOCKER",
          "title": "Spigot-mapped NMS names",
          "titleRu": "Spigot-маппинги NMS",
          "why": "...",
          "fix": "...",
          "evidence": ["EntityPlayer → ServerPlayer", "NBTTagCompound → CompoundTag"]
        }
      ]
    }
  ]
}
```

Правила совместимости формата: поля не удаляются и не переименовываются в пределах мажорной версии;
новые поля могут добавляться; `id` находки — стабильный ключ.

## 6. Нефункциональные требования

| Требование | Значение | Как проверено |
|---|---|---|
| Размер jar | < 100 КБ | 70 720 байт |
| Runtime-зависимости | 0 | build.gradle.kts, только `compileOnly` |
| Скорость | < 5 с на 50 плагинов | 8 фикстур за 41 мс |
| Безопасность | код плагинов не загружается и не исполняется | jar читается как zip, класс — как поток байт |
| Главный поток | не блокируется | сканирование в async-планировщике |
| Folia | **не поддерживается**, `folia-supported: false` | планирование идёт через `BukkitScheduler`, который на Folia бросает `UnsupportedOperationException`. Сканер ничего не знает о сущностях и мире, так что переезд на региональные планировщики — небольшая работа, но пока она не сделана и не проверена на живой Folia, флаг остаётся выключенным. На Folia работает режим CLI |
| Целевая Java | 17 | `--release 17` |
| Кодировка | UTF-8 принудительно | `-encoding UTF-8`, `PrintStream` с явным UTF-8 |

Про UTF-8 отдельно: в RU-комьюнити регулярная боль — «иероглифы в консоли». Все потоки вывода
создаются с явной кодировкой, поэтому русский отчёт не зависит от `file.encoding` сервера.

## 7. Тестирование

Самотест `tools/offline/selftest.sh` собирает синтетические jar-ы, содержащие ровно те байтовые
паттерны, которые ищет каждое правило, прогоняет сканер и проверяет JSON.

Фикстуры:

| jar | Ожидание |
|---|---|
| `LegacyPlugin` | КРАСНЫЙ: Spigot-маппинги + версионный CraftBukkit + version-рефлексия + нет api-version |
| `ModernPlugin` | ЗЕЛЁНЫЙ, поднят флаг Folia, версия распарсена |
| `DeprecatedPlugin` | ЖЁЛТЫЙ: Conversation + Metadata + PlayerSpawnLocationEvent + TeleportFlag |
| `DepsPlugin` | предупреждение про ProtocolLib из `depend` |
| `SusPlugin` | четыре SECURITY-находки, при этом вердикт остаётся ЗЕЛЁНЫМ |
| `PlainLibrary` | опознан как «не плагин» |
| `BrokenMain` | КРАСНЫЙ: главного класса нет в архиве |
| `Corrupt.jar` | ПРОПУЩЕН, сканер не падает |

Отдельно проверяется поставляемый `config.yml`: настоящий загрузчик запускается на настоящем файле
и его значения сверяются с ожидаемыми. Заголовок конфига — стена рамок из псевдографики, и опечатка
в ней ничего бы не уронила: плагин молча вернул бы все значения по умолчанию, а настройки админа
были бы проигнорированы без единой строчки в логе.

31 утверждение, все зелёные. Запуск: `bash tools/offline/verify.sh` или `gradle selftest`.

Из внешних программ самотесту нужны только `javac`, `java`, `bash` и `perl` — всё это приходит
вместе с JDK и с Git, поэтому набор одинаково запускается на машине разработчика под Windows и в
Linux-CI. Гейт, который работает только в CI, гейтом не является.

Ключевой принцип: фикстуры компилируются против временных заглушек, а в jar кладутся **только**
классы фикстуры. Ссылки на «серверные» классы остаются в constant pool, определений нет — ровно
как в настоящем плагине.

## 8. Сборка

**Обычная:** `gradle build` → `build/libs/SNDoctor-1.0.0.jar`. Единственная зависимость —
`compileOnly("io.papermc.paper:paper-api:1.21.4-R0.1-SNAPSHOT")`.

Gradle-wrapper в репозиторий намеренно не кладётся: `gradle-wrapper.jar` — это бинарник, который
пришлось бы принимать на веру, а проект ровно про то, чтобы бинарники на веру не принимать.
Основной путь сборки — офлайн-скрипт ниже, ему нужен только JDK.

**Офлайн:** `bash tools/offline/build-offline.sh`. Компилирует против крошечных compile-only
заглушек Bukkit из `tools/offline/bukkit-stubs`, которые **не попадают** в jar. Существует для
случая, когда Maven Central или repo.papermc.io недоступны — для машины в РФ это рабочая ситуация,
а не экзотика.

Обе сборки дают функционально одинаковый jar.

## 9. Дорожная карта

### v1.1
- Поддержка Folia: перевод планирования на региональные планировщики и проверка на живой Folia,
  после которой `folia-supported` можно честно поднять в `true`
- HTML-отчёт (это то, что реально скринят и репостят)
- Поиск живых замен для красных плагинов через API Modrinth и Hangar
- Обновление таблицы имён и правил из сети, с офлайн-фолбэком на встроенные
- Флаг `--only red` и `--fail-on yellow` для CI

### v1.2
- Отправка отчёта в Telegram
- Сравнение двух отчётов: «что изменилось после обновления плагинов»
- Публичная таблица «плагин → статус на 26.x», собираемая из обезличенных отчётов
  (только с явного согласия, отдельным флагом)

### Осознанно не делаем
- Автообновление плагинов — отдельный продукт с отдельными рисками.
- Бинарный поиск «какой плагин ломает сервер» — отдельный инструмент, ему нужны перезапуски сервера.
