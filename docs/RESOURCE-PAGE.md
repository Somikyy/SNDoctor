## Краткое описание

> Читает каждый jar в папке plugins и говорит, что именно не запустится на Minecraft 26.x.
> Работает из командной строки, без запуска сервера — то есть тогда, когда он нужнее всего.
> Ноль зависимостей, чужой код не загружается, 70 КБ, открытый исходный код.

**Сокращённый вариант (для поля «tagline»):**

> Проверяет, что из твоих плагинов сломается при переходе на 26.x — до того, как ты обновишься.

## Поддерживаемые версии

SNDoctor — инструмент, а не игровая механика, поэтому таблица здесь про то, где он **запускается**,
а не про то, что он умеет проверять. Проверять он умеет плагины под любые версии.

| Где | Статус |
|---|---|
| **Режим командной строки** | Любая ОС с Java 17+. Сервер не нужен вообще |
| **Плагин на Paper 1.21+** | Собрано под `api-version: 1.21` |
| **Spigot, CraftBukkit, Purpur, Pufferfish и прочие форки** | Из серверного API используются пять базовых классов Bukkit, Paper-only API в коде нет |
| **Folia** | `folia-supported: false` — честно. Пользуйся режимом командной строки |

> ⚠️ Список ядер, на которых ты гонял плагин лично, подставь сюда сам — я их не видел.

## Минимальная версия Java

**Java 17.**

Ниже, чем у большинства современных плагинов, и это осознанно: SNDoctor должен запускаться на тех
самых старых серверах, которые он и диагностирует. На 21 и 25 работает.

## Описание

### Проблема

С версии **26.1** Mojang перестал отдавать обфусцированные server-jar'ы, а Paper полностью выкинул
внутренний ремаппер. Формулировка PaperMC дословно: плагин со Spigot-маппингами **«не будет
работать на 26.1, независимо от того, Paper у вас или нет»**.

Масштаб (данные Modrinth на 1 августа 2026):

| Версия | Плагинов с поддержкой |
|---|---|
| 1.21.4 | 12 631 |
| 26.1 | 4 264 |
| **26.2** | **2 532** |
| всего плагинов на Modrinth | 16 482 |

Примерно **85% экосистемы ещё не перешло рубеж**. А узнать, что именно сломается на твоей сборке,
до сих пор можно было ровно одним способом: обновиться и смотреть, что упало.

### Решение

SNDoctor читает каждый jar в папке `plugins` как zip-архив, каждый class-файл — как поток байт, и
выносит вердикт по каждому плагину:

- **красный** — не запустится;
- **жёлтый** — запустится, но что-то сломано или устарело;
- **зелёный** — проблем не найдено.

Главное: **сервер запускать не нужно**. Проверять надо тогда, когда сервер ещё работает на старой
версии или уже не стартует на новой.

```
java -jar SNDoctor.jar plugins --java 25
```

Каждая находка — это не просто «плохо», а три вещи: **что нашли**, **почему это ломается** и
**что с этим делать**.

### Чем отличается от того, что уже есть

Прямого аналога я не нашёл. Ближайшее по смыслу — платные решения про автообновление плагинов, но
обновление и совместимость с новой мажорной версией — разные задачи: автообновление подтянет тебе
новую версию плагина, если она есть, и промолчит про плагин, который просто заброшен.

Канонический совет комьюнити по диагностике до сих пор звучит как «читай логи и убирай плагины по
одному». Это работает, но занимает вечер и требует запущенного сервера.

### Три правила, на которых он построен

**1. Чужой код никогда не выполняется.** SNDoctor не загружает и не запускает проверяемые плагины.
Jar читается как архив, class — как байты. Проверяемый плагин не оказывается в JVM ни на секунду.
Для инструмента, которому дают папку с непроверенными jar-ами, это не опция.

**2. Ноль зависимостей.** Ни ASM, ни SnakeYAML, ни JSON-библиотеки — свой ридер class-файлов и свой
ридер YAML. Итоговый jar — около 70 КБ. Инструмент, который кладут на уже сломанный сервер, не
должен приносить с собой ещё один способ конфликтовать с classpath. И 70 КБ открытого кода
проверяются глазами за вечер — после истории с бэкдором в мае 2026 это не лишнее.

**3. Ни одного правила «по ощущениям».** Каждое опирается на первоисточник: анонс PaperMC, пометку
deprecated в javadoc или наблюдаемое свойство самого jar.

Два правила-кандидата **проверены и намеренно не добавлены**, потому что подтверждения не нашлось:
смена идентификаторов геймрулов с camelCase на snake_case и переход методов длительности
`WorldBorder` с миллисекунд на тики. Ни того, ни другого нет в анонсе Paper 1.21.9/1.21.10 — значит,
правила нет.

Одно ложное «не запустится» стоит дороже десяти пропущенных проблем: админ, которому соврали про
рабочий плагин, дальше не поверит ни одной строчке отчёта. И будет прав.

### Что проверяется

**23 правила совместимости и 5 эвристик безопасности.**

*Не запустится:*
- Spigot-маппинги NMS (по таблице из 105 имён)
- версионные пакеты `net.minecraft.server.v1_XX_RX` и `org.bukkit.craftbukkit.v1_XX_RX`
- главный класс из `plugin.yml` отсутствует в архиве
- плагину нужна Java новее, чем на сервере

*Сломано или устарело:*
- `TeleportFlag.EntityState` — больше не имеет функциональности
- Conversation API, Metadata API, `PlayerSpawnLocationEvent`
- легаси-API предметов до 1.13, отсутствие или древний `api-version`
- зависимость от ProtocolLib

*На ручную проверку (на вердикт не влияет):*
- запуск внешних процессов, загрузка кода во время работы
- обращения к сырым IP, пейстбинам и вебхукам
- чтение `rcon.password`, `ops.json`, `usercache.json`
- одиночные классы внутри пакета известной библиотеки

Про последний пункт отдельно. Настоящий шейдинг библиотеки приносит сотни её классов. Если внутри
`org/apache/commons/lang3/` лежит один класс — это не шейдинг, это чужой код в чужом пакете. Ровно
такой формы был бэкдор, разобранный в RU-комьюнити в мае 2026.

Секция безопасности **не влияет** на вердикт совместимости: «стоит посмотреть глазами» и
«запустится ли» — разные вопросы, и смешивать их значило бы врать светофором.

### Три режима работы

**1. До обновления, из командной строки.** Основной сценарий. Сервер не нужен.

```
java -jar SNDoctor.jar plugins --java 25
```

Код возврата: `2` — есть красные, `1` — есть жёлтые, `0` — чисто. Годится для скрипта:

```
java -jar SNDoctor.jar plugins --java 25 || echo "не обновляемся"
```

**2. На живом сервере, командой.** `/sndoctor scan` — сводка в чат, полный отчёт в файл.
Сканирование асинхронное, главный поток не трогается.

**3. Само, при запуске сервера.** По умолчанию проверка идёт через пять секунд после старта, итог
пишется в консоль. Обновил ядро, поднял сервер — и сразу видно, что не завелось.

### Флаги командной строки

| Флаг | Смысл |
|---|---|
| `--java <N>` | Java, на которой будет крутиться сервер |
| `--json <файл>` | машинный отчёт для бота, панели или CI |
| `--out <файл>` | полный текстовый отчёт в файл |
| `--names <файл>` | свой список Spigot-имён поверх встроенного |
| `--lang ru\|en` | язык вывода, по умолчанию русский |
| `--full` | показывать справочные находки и зелёные плагины |
| `--no-color` | без ANSI-цветов |

## Настройка

Весь конфиг — десяток строк в `plugins/SNDoctor/config.yml`:

```yaml
general:
  language: ru          # язык отчёта: ru или en
  update-check: true    # один async-запрос к api.github.com при старте
                        # false = плагин не ходит в сеть вообще никогда

scan:
  on-start: true        # проверять плагины при запуске сервера
  start-delay: 100      # задержка перед автопроверкой, в тиках
  full: false           # включать ли справочные находки

reports:
  enabled: true         # писать отчёты в plugins/SNDoctor/reports/
  json: true            # дополнительно писать машиночитаемый .json
  keep: 20              # сколько последних проверок хранить, 0 = не удалять
```

Никакой телеметрии и никакой статистики плагин не собирает и не отправляет.

## Расширение таблицы имён

Список Spigot-имён (105 записей) лежит внутри jar и расширяется **без пересборки**:

- режим плагина: `plugins/SNDoctor/spigot-names.txt`
- режим CLI: `--names my-names.txt`

Формат — `SpigotName=MojangName`, строки с `#` игнорируются. Твои записи добавляются поверх
встроенных.

Нашёл имя, которого не хватает? Присылай на GitHub — это самый простой способ помочь проекту.

## Зависимости

**Обязательных нет. Опциональных тоже нет.** Плагин самодостаточен: ни одной библиотеки внутри, ни
одного депенда снаружи. Единственная зависимость сборки — API сервера, и та `compileOnly`.

## Команды и права

Основная команда: `/sndoctor`. Алиасы: `/snd`, `/sndoc`, `/снд`.

| команда | что делает | право |
|---|---|---|
| `/sndoctor` | без аргументов сразу запускает проверку — то же, что `scan` | `sndoctor.use` |
| `/sndoctor scan` | сводка в чат, полный отчёт в файл | `sndoctor.use` |
| `/sndoctor full` | то же плюс справочные находки и список зелёных | `sndoctor.use` |
| `/sndoctor version` | версия плагина и цель проверки | `sndoctor.use` |
| `/sndoctor reload` | перечитать `config.yml` без рестарта сервера | `sndoctor.reload` |
| `/sndoctor help` | список команд | `sndoctor.use` |

Флаги работают и в игре, не только в командной строке:

| флаг | смысл |
|---|---|
| `--lang ru\|en` | язык отчёта на один запуск, перекрывает `config.yml` |
| `--full` | то же, что подкоманда `full` |

Например: `/snd scan --lang en --full`

Автодополнение по Tab работает и у подкоманд, и у флагов, и у значений `--lang`.

Проверка идёт асинхронно, главный поток не трогается. В чат уходит сводка и первые десять
красных, полный отчёт пишется в `plugins/SNDoctor/reports/`. Пока проверка идёт, повторный
запуск вторую не стартует.

### Права

| право | по умолчанию | что даёт |
|---|---|---|
| `sndoctor.use` | оператор | доступ к команде: запуск проверки, просмотр отчёта, версия |
| `sndoctor.reload` | оператор | перезагрузка `config.yml` |

**Важная деталь.** Вся команда закрыта правом `sndoctor.use` на уровне `plugin.yml`, поэтому
одного `sndoctor.reload` не хватит: без `sndoctor.use` игрок не сможет ввести команду вообще.

Пример настройки групп (LuckPerms) — хелперу только смотреть, администратору всё:

```
/lp group helper permission set sndoctor.use true

/lp group admin permission set sndoctor.use true
/lp group admin permission set sndoctor.reload true
```

Если раздавать права никому не нужно — не делай ничего: оба права по умолчанию есть только
у операторов.

## Установка

1. Скачай `SNDoctor-26.8.1.jar`
2. Положи в папку `plugins/`
3. Перезапусти сервер

Конфиг создастся сам при первом запуске. Ставить рядом ничего не надо.

Для проверки без запуска сервера тот же самый файл запускается напрямую:

```
java -jar SNDoctor-26.8.1.jar plugins --java 25
```
